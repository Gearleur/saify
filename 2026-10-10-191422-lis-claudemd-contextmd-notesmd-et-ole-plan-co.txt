  Ce que fait l'étape. Chaque transformation des données sources est tracée dans
  le journal à l'un des 4 niveaux :

  ┌───────────┬────────────────────────┬─────────────────────────────────────┐

  ├───────────┼────────────────────────┼─────────────────────────────────────┤
  │           │ Ligne retirée en vertu │ P3G, ligne sans sous-compte, item   │
  │ EXCLU     │  d'une règle client    │ ACTION=S                            │
  │           │ citée                  │                                     │
  ├───────────┼────────────────────────┼─────────────────────────────────────┤
  │           │ Ligne conservée mais   │ clé ISIN invalide, ISIN hors        │
  │ SIGNALE   │ douteuse, un humain    │ référentiel, libellés différents    │
  │           │ regarde                │                                     │
  ├───────────┼────────────────────────┼─────────────────────────────────────┤
  │           │ Fichier refusé, donc   │ mauvaise date, total de contrôle    │
  │ BLOQUANT  │ aucun suspens produit  │ faux, transco inconnue, quantité    │
  │           │                        │ illisible                           │
  └───────────┴────────────────────────┴─────────────────────────────────────┘

  Pourquoi. Le client doit pouvoir répondre à « pourquoi cette ligne n'est-elle
  pas dans le rapprochement ? » sans lire le code. C'est la traçabilité
  demandée.

  Ce que je trouve en relisant, du plus grave au moins grave

  1. Des lignes jetées sans trace : c'est le pire défaut, car il crée des faux
  négatifs invisibles.
  - Fichier A : if compte is None: continue. Une ligne qui a un ISIN et une
    quantité mais une cellule de compte vide (cellule fusionnée, oubli)
    disparaît sans aucune trace.
  - Fichier B : une ligne qui ne commence ni par H, ni par D, ni par T (un d
    minuscule, un type inconnu) est ignorée. Le total de contrôle la rattrape
    peut-être, mais seulement si T compte toutes les lignes.
    → Je propose : une ligne vraiment vide est ignorée ; une ligne partiellement
    remplie ou d'un type inconnu → BLOQUANT.

  2. Un ACTION inconnu chez C est traité comme une position valide.
  Seul S est exclu. Un M (modification) ou un X serait additionné tel quel. On
  ne connaît pas le sens de ces codes, donc on ne doit pas deviner → BLOQUANT
  ACTION_INCONNUE.

  3. "10.000" est lu comme 10 sans aucun signal.
  Si un conservateur envoie un jour un point comme séparateur de milliers,
  Decimal("10.000") vaut 10 : un QTE faux et silencieux. Même chose pour une
  quantité négative.
  → Une quantité non entière ou négative → SIGNALE. Ça ne bloque pas, parce
  qu'un nominal peut légitimement avoir des décimales.

  4. Le paramétrage n'est pas contrôlé du tout.
  - S'il manque un code dans TYPES_ECARTS (par exemple pas de DEP), le programme
    plante au lieu de bloquer proprement.
  - Si un même sous-compte apparaît deux fois dans la transco avec deux fonds
    différents, le dernier gagne sans rien dire.
    → Paramétrage invalide → BLOQUANT, avec une ligne dans le journal.

  5. Une question de fond : un seul BLOQUANT bloque tout.
  Imagine qu'un matin, un nouveau sous-compte n'a pas encore été ajouté à la
  transco. On obtient zéro suspens sur les 3 fonds, et l'opérateur repart sur 1
  h 30 de travail manuel.
  Je défends quand même ce choix : un sous-compte inconnu, c'est un fonds
  inconnu, donc on ne peut garantir aucun fonds. Et un fichier conservateur
  rejeté produirait de faux ABS_DEP en masse. Par contre, le message doit dire
  quoi faire (« ajouter SC-XXX à TRANSCO_SOUS_COMPTES puis relancer »), pas
  seulement « bloqué ».

  6. Défauts mineurs
  - Si le fichier n'est pas en UTF-8, on retombe sur latin-1 sans le noter. Il
    faudrait au moins une ligne NORMALISE ENCODAGE.
  - Une colonne renommée dans le CSV fait apparaître KeyError : 'quantite', un
    message incompréhensible pour un opérateur. Il faudrait un vrai contrôle
    d'en-tête.
  - Le journal contient 69 NORMALISE : c'est utile pour l'audit mais c'est du
    bruit pour l'opérateur. La page devra filtrer par niveau (étape 3).

  Tes décisions

  1. Lignes partiellement remplies ou de type inconnu → BLOQUANT : d'accord ?
  2. ACTION inconnu chez C → BLOQUANT ou SIGNALE ?
  3. Quantité non entière ou négative → SIGNALE, plutôt que BLOQUANT ?
  4. Point 5 : on garde le blocage total avec un message actionnable, ou tu
     préfères une autre granularité ?
